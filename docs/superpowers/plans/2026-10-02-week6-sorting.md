# 6주차 정렬 알고리즘 실습 구현 계획

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 6주차 이론에 맞춘 도전문제 4개와 추가문제 1개를 노트북과 독립 실행 HTML로 만들고 기존 GitHub 저장소에 push한다.

**Architecture:** 노트북을 수업 내용의 원본으로 삼는다. 5주차 HTML의 수업 진행 UI를 재사용하되 코드 해설, 실행 기록과 상태 표현을 정렬에 맞게 교체한다. Python 실행으로 생성한 기록을 HTML에 포함한다.

**Tech Stack:** Python, Jupyter nbformat 4, HTML/CSS/JavaScript, PNG, Playwright.

**Spec:** 사용자의 요청, `docs/실습_자료_제작_가이드.md`, `docs/웹사이트_제작_가이드.md`, 아래 설계 결정.

## 근거와 설계 결정

- 전체 폴더의 파일 목록과 기존 1~5주차 노트북, 웹 구성, 이미지, 검증 스크립트를 확인한다. 이론 PDF들의 목차를 비교해 이후 주차의 개념을 구분한다.
- 이번 학기 강의계획서 3쪽: 6주차는 버블/선택/삽입 정렬과 성능 분석. 합병/퀵 정렬은 13주차이므로 요구하지 않는다.
- 6주차 교안 20~24쪽: 버블 정렬과 조기 종료. 25~33쪽: 선택 정렬. 34~42쪽: 삽입 정렬. 7~14, 23, 31~32, 40~41쪽: 연산 수 분석. 16, 19쪽: 키와 안정성.
- 도전1 `bubble_sort(weights)`: 인접 원소를 교환하는 기본 오름차순 버블 정렬. 원본 리스트를 수정하고 반환값은 사용하지 않는다.
- 도전2 `selection_sort(scores)`: 최댓값 위치를 찾아 앞쪽과 교환하는 내림차순 선택 정렬. 중복 점수도 유지한다.
- 도전3 `insertion_sort(records)`: `(이름, 기록)` 튜플을 기록 오름차순으로 정렬. 같은 기록의 접수 순서를 유지한다. 이동 중인 항목은 `key`로 따로 보관한다.
- 도전4 `bubble_count(values)`, `selection_count(values)`: 오름차순 정렬하고 원소 값끼리 비교한 횟수만 반환한다. 선택 정렬은 제공하며 버블 정렬의 조기 종료와 계수를 학생이 구현한다. `n=0,1`은 0회. 정렬된 길이 n>=2의 버블은 n-1회, 선택은 n(n-1)/2회. 서로 다른 역순 입력은 둘 다 n(n-1)/2회. 같은 원본의 독립 복사본을 사용한다.
- 추가1 `rank_entries(entries)`: 도전3의 삽입 정렬을 점수 내림차순으로 응용. 동점은 접수 순서 유지. 앞의 k명만 출력하며 k=0은 `선발된 참가자가 없습니다.`를 출력한다. 새 알고리즘은 도입하지 않는다.

## Global Constraints

- 파일: `practice/6주차 실습.ipynb`, `website/week6_prac.html`, `images/week6/week6_chal1.png`~`week6_chal4.png`, `week6_extra1.png`.
- 문제마다 제목/가로형 그림/조건과 예시/스켈레톤/Solution/테스트 Markdown 순서. 테스트 정확히 4개이며 1번은 기본 예시와 일치한다.
- 짧은 input 프롬프트, `# To Do`, 핵심 구역의 `# Sol:` 주석. 첫 pass의 의미를 안내한다. 정렬 내장 함수는 금지한다.
- 출력 예시와 테스트는 프롬프트와 입력을 포함한 실행 화면. 웹 출력 패널은 print 결과만 표시한다고 도움말에 안내한다.
- 실습 자료에 가운데점 금지. 입출력 코드 블록은 언어 이름을 붙이지 않는다.
- 기존 로더, 접근성, 키보드, 복사, 모달, 모바일 대응을 유지. 이미지와 글꼴을 HTML에 포함해 외부 요청 없이 작동한다.
