# 웹사이트 제작 가이드

[실습 목차](../website/main.html)와 현재 1·2·3주차 웹페이지의 구성 및 승인된 수정 사항을 기준으로 한다. 객체 지향 개념의 시각화는 [3주차 실습 노트북](<../practice/3주차 실습.ipynb>)과 [3주차 웹페이지](../website/week3_prac.html)를 참고한다. 학생은 Elice에서 풀이하고, 웹페이지는 수업 설명과 시연을 돕는다. 노트북 자체의 제작 기준은 [실습 자료 제작 가이드](실습_자료_제작_가이드.md)를 따른다.

## 1. 원본과 학습 흐름

- 입력은 `practice/{n}주차 실습.ipynb`, 결과물은 `website/week{n}_prac.html`로 저장한다.
- 완성된 노트북을 내용의 기준으로 삼는다. 문제 수와 순서, 조건, 변수명, 입출력 형식, 학생 작성 범위를 보존하고 도입 예제와 추가문제도 반영한다.
- 웹페이지에서 삭제하도록 요청받은 소개나 문구는 노트북에 남아 있어도 복원하지 않는다. 1주차 웹페이지의 조교 소개는 제거된 상태를 유지하고, Elice 안내와 실습 내용은 보존한다.
- 문제 설명, 그림, 스켈레톤, Solution, 테스트 케이스를 문제별로 묶는다. 긴 설명은 소제목과 표로 정돈하되 조건이나 작성 안내를 생략하지 않는다.
- 개념 도식과 짧은 해설은 해당 주차의 학습 범위 안에서 보완한다. 도식에 예시를 추가했다면 실제 코드가 다루는 대상과 구분해 안내한다.

## 2. 세 단계 화면

| 단계 | 화면 구성 | 핵심 동작 |
| --- | --- | --- |
| 문제 설명 | 왼쪽 문제 전문, 오른쪽 상황 그림 또는 개념 도식 | 그림은 원래 비율로 표시하고 클릭하면 크게 본다. |
| 코드 구현 | 왼쪽 입출력 형식과 기본 예시, 오른쪽 코드와 짧은 해설 | 학생용 스켈레톤에서 시작해 필요한 코드를 한 줄씩 채운다. |
| 코드 확인 | 왼쪽 완성 코드, 오른쪽 실행 상태와 누적 출력 | 선택한 예제의 실행을 단계별로 재생하고 현재 코드 줄과 상태를 함께 강조한다. |

## 3. 코드 구현과 실행 시각화

- **원본 코드 유지:** 스켈레톤의 제공 코드와 주석을 처음부터 보여 준다. 구현할 부분만 채우고 해당 `pass`는 교체한다. 완성 코드는 Solution과 동일하게 동작해야 한다.
- **작성 순서 설계:** 입력과 호출부를 확인한 뒤 필요한 함수나 클래스로 이동해 구현하고 돌아오는 흐름을 활용한다. 설명을 위한 작성 순서와 실제 실행 순서를 구분하고, 완성 코드의 정의 위치와 들여쓰기는 유지한다.
- **한 단계에 한 초점:** 새 줄의 타이핑 효과, 현재 줄 강조, 자동 스크롤, 1~2문장의 해설을 연결한다. 빠르게 넘기거나 뒤로 이동해도 코드가 중복되거나 애니메이션이 남지 않게 한다.
- **검증한 실행 기록:** 3주차처럼 원본 Python을 실행해 얻은 기록을 재생한다. 입력, 호출과 복귀, 조건 분기, 반복, 반환값, 상태 변화, 출력을 실제 실행과 맞춘다. 도움말에는 예제 실행 기록의 재생 방식임을 밝힌다.
- **개념에 맞는 표현:** 3주차는 객체 식별자, 변수와 `self`의 참조, 속성의 이전 값 → 새 값, 호출 흐름과 잔여 수량을 보여 준다. 다음 주차는 학습 대상에 맞춰 리스트와 인덱스, 반복 과정 등의 표현을 선택한다. 교육용 표기의 의미도 짧게 설명한다.
- **예제와 출력:** 노트북의 테스트 케이스를 모두 반영하고 각 사례의 의미를 선택 메뉴에 표시한다. 예제를 바꾸면 실행 상태와 출력을 초기화한다. 기본 입출력 예시와 선택한 실행 사례를 구분하고, 실행 출력에서 입력 안내 문구를 생략한다면 도움말에 명시한다.

## 4. 수업 진행 기능

- 상단에 현재 문제와 목차, 하단에 단계 선택, 진행 번호, 이전/다음 버튼을 둔다. 다음 버튼 문구는 코드 구현 시작, 다음 줄, 다음 실행, 다음 문제처럼 현재 동작을 알려 준다.
- 상단의 네 칸 로고는 전체 주차 목차인 `main.html`로 연결한다. 현재 실습 안의 문제 메뉴와 전체 주차 이동을 구분하고, 키보드로도 이동할 수 있게 한다.
- 현재 단계 다시 시작과 현재 문제 처음부터를 구분한다. 이전 이동 시 코드와 실행 상태도 해당 시점으로 되돌린다.
- 단축키는 `→`/`Space` 다음, `←` 이전, `Page Up`/`Page Down` 문제 이동, 숫자 키로 바로 이동, `F` 전체 화면, `?` 도움말, `Esc` 닫기를 제공한다. 숫자 범위는 실제 화면 수에 맞춘다.
- 코드 복사는 현재 단계에 공개된 코드와 주석을 복사한다. 실행 단계에서는 완성 코드를 복사하며, 자동 복사가 실패하면 직접 선택해 복사할 수 있게 한다. 전체 화면을 사용할 수 없을 때는 화면을 넓히는 대체 동작을 둔다.
- 도움말에 진행 방식과 단축키를 모으고, 마지막에는 해당 주차의 핵심 개념과 짧은 복습 질문을 보여 준다.

## 5. 디자인과 접근성

- **수업 화면의 일관성:** 흰 배경, 녹색 계열 강조색, 어두운 코드 영역을 기본으로 한다. 여백과 패널 간격을 충분히 두고 장식보다 문제, 코드, 상태 변화가 눈에 들어오게 한다.
- **멀리서 읽는 글자:** 본문 약 24px, 코드 약 22px를 기준으로 화면 크기에 맞춘다. 코드는 고정폭 글꼴과 문법 강조를 사용하고, 긴 한국어 설명은 문장 단위로 나눈다. 줄바꿈이 코드의 들여쓰기나 복사 내용을 훼손하지 않게 한다.
- **화면 크기 대응:** 큰 화면에서는 나란히 배치하고 작은 화면에서는 세로로 쌓는다. 긴 문제, 코드, 실행 상태는 각 영역에서 스크롤하며 조작 버튼과 현재 단계가 가려지지 않게 한다.
- **키보드와 모달:** 버튼 이름, 이미지 대체 텍스트, 포커스 표시를 제공한다. 모달 안에서 포커스가 순환하고 닫으면 원래 요소로 돌아오게 한다. 선택 메뉴나 입력란 조작 중에는 수업 이동 단축키가 개입하지 않게 한다.
- **변화 전달:** 색상과 함께 화살표, 수치, 설명으로 변화를 표시한다. 동작 줄이기 설정에서는 타이핑과 상태 변화 애니메이션을 생략한다.

## 6. 파일 구성과 주차별 갱신

- GitHub Pages는 `main` 브랜치 루트에서 직접 배포한다. 루트의 `index.html`은 `website/main.html`로 이동하며, `404.html`은 이전 루트 페이지 주소를 `website/` 아래 주소로 연결한다. `.nojekyll`을 유지하고 `.github/workflows` 없이 배포한다.
- HTML 하나에 CSS, JavaScript, 수업 데이터, 실행 기록, 그림과 필요한 글꼴을 포함한다. 외부 CDN이나 서버 요청 없이 Windows와 macOS에서 파일을 직접 열어 사용할 수 있게 한다.
- 문제 그림 원본은 `images/week{n}/week{n}_chal{k}.png` 또는 `images/week{n}/week{n}_extra{k}.png`에서 읽어 HTML 내부에 데이터 URL로 포함한다. 노트북의 `../images/week{n}/` 경로는 `practice/` 기준으로 해석한다. 이미 그림을 포함한 HTML은 원본 폴더 이동만으로 수정할 필요가 없지만, 그림 내용이 바뀌면 포함 이미지도 갱신한다.
- 주차명, 문제 수와 추가문제 위치, 단축키 범위, 입출력 요약, 줄별 해설, 시각화, 마무리 문구를 함께 갱신한다. 3주차 HTML의 문제 ID, 클래스명, 속성명에 따른 조건 분기도 확인한다.
- 새 주차에 등장하는 Python 문법의 강조, Markdown 표와 코드 블록, HTML 특수문자 표시를 확인한다. 포함 글꼴의 새 한글 지원을 확인하고 기존 저작권과 라이선스 고지를 유지한다.

## 7. 로딩 화면

- 기존 녹색 계열과 네 칸 로고를 사용한다. 로고 전체를 회전시키지 않고 강조색을 왼쪽 위 → 오른쪽 위 → 오른쪽 아래 → 왼쪽 아래 순서로 바꾼다. 화면 중앙에는 로고를 표시하고, 불러오는 중이라는 설명은 스크린리더에 제공한다.
- 로더의 CSS와 초기화 코드는 큰 포함 글꼴과 수업 데이터보다 먼저 배치한다. 현재처럼 로더 마크업 뒤에 포함 글꼴을 두어 HTML을 내려받는 중에도 로고를 표시할 수 있게 한다. 별도 이미지나 외부 글꼴 다운로드에 의존하지 않는다.
- 목차의 실습 링크를 누른 직후와 주차별 주소에 직접 접속했을 때 모두 표시한다. 첫 화면의 그림과 글꼴이 준비되면 숨기고, 애니메이션을 보여주려고 최소 대기 시간을 추가하지 않는다. 자원 준비나 이동이 실패했을 때 로더가 화면을 계속 가리지 않도록 기존 대기 상한을 유지한다.
- 이전 주소에서 실제 페이지로 연결하는 중에는 이전 문서의 준비 완료 이벤트가 로더를 먼저 숨기지 않게 한다. 뒤로 가기로 돌아오면 로딩 표시와 입력 제한을 해제한다. 새 탭 열기와 보조 키를 누른 링크 클릭은 브라우저 기본 동작을 유지한다.
- `prefers-reduced-motion` 설정에서는 정지된 로고를 보여 준다. 로딩 중에는 본문 조작을 제한하고, 완료 후에는 키보드와 포커스 동작을 복구한다.
- 공통 로더를 바꾸면 `website/main.html`, 제작된 주차별 HTML, 루트의 `404.html`에도 같은 변경을 반영한다.

## 8. 목차, README와 배포 주소

- `website/main.html`은 1주차부터 15주차까지의 주제와 일정을 표시한다. 일정과 범위는 이번 학기 강의계획서에 맞춘다. 실제 웹페이지가 완성된 주차에만 실습 열기 링크를 제공하고, 행 전체가 아닌 링크를 눌렀을 때 이동하게 한다.
- README는 수업 소개 한 문장, 실습 사이트 주소, 주차별 표, 주요 자료 구성만 간결하게 유지한다. 사이트 표기는 `실습 사이트: https://sumin-kim.com/Computing-2026-Fall`로 쓴다. 조교용이라는 설명, 로컬 보관 및 검증 안내, 배포 절차와 물결표시는 넣지 않는다. 상세 제작 및 관리 기준은 이 가이드에 둔다.
- README 표는 15주차까지 유지하며, 주제명은 `main.html`의 주차별 제목과 정확히 일치시킨다. 노트북과 웹 실습 열을 별도로 두고 완성된 자료에만 링크를 채운다. 현재 1·2·3주차에는 두 링크를 제공하고, 4주차 이후의 링크 칸은 공란이다.
- 노트북 링크는 `practice/{n}주차 실습.ipynb`, README의 웹 링크는 `https://sumin-kim.com/Computing-2026-Fall/week{n}_prac.html` 형식을 사용한다. 실제 HTML은 `website/week{n}_prac.html`에 있으므로 새 주차를 공개할 때는 `404.html`의 연결 대상 목록에도 해당 파일명을 추가한다. 이미 공유한 주소는 계속 사용할 수 있게 유지한다.
- 배포 설정은 GitHub Pages의 `Deploy from a branch`, `main`, `/(root)`를 유지한다. 푸시 후 배포가 완료되면 사이트 첫 화면, README의 웹 주소, 실습에서 목차로 돌아오는 링크를 확인한다.

## 10. 검증 실행

`tests/`의 검증 스크립트가 있는 작업 환경에서는 저장소 루트에서 아래 명령을 실행한다. 스크립트는 GitHub에 포함하지 않으며, 실행에는 `nbformat`, `Pillow`, `Playwright`와 Chromium이 필요하다. 문서만 수정할 때는 링크와 내용의 일치 여부를 점검하고, 웹 동작을 바꿀 때는 관련 브라우저 검사를 실행한다.

```bash
python -m unittest discover -s tests -v
python tests/check_practice_browser.py -v
python tests/check_loading_browser.py -v
```

새 주차를 만들면 해당 자료도 검사 범위에 추가한다. 기존 검사가 통과하더라도 새 문제의 실행 결과와 새 페이지의 동작은 별도로 확인한다.
