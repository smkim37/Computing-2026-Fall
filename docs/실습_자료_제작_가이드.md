# 컴퓨팅 핵심 실습 자료 제작 가이드

## 목적과 기준 자료

`"@@ 이론 개념을 다루는 n주차 실습 자료를 만들어줘"`라는 요청을 받으면 해당 주차의 `ipynb` 실습 자료를 제작한다. 이번 학기 강의계획서를 가장 먼저 확인하고, 해당 개념의 이론 교안을 검토해 오전 수업과 범위를 맞춘다. 지난 학기 자료는 설명 방식과 난이도를 참고하는 용도로만 사용한다. 사용자가 이미 완성하거나 승인한 내용은 임의로 바꾸지 않는다.

## 파일 위치

아래 저장 경로는 저장소 루트를 기준으로 한다.

- 실습 노트북: `practice/{n}주차 실습.ipynb`
- 문제 그림: `images/week{n}/week{n}_chal{k}.png` 또는 `images/week{n}/week{n}_extra{k}.png`
- 이번 학기 강의계획서: [2026-2학기 컴퓨팅핵심 강의계획서](<2026-2학기 컴퓨팅핵심 강의계획서.pdf>)
- 이전 학기 이론 참고 자료: `2026-1학기 이론 교안/` (로컬 전용, GitHub 업로드 제외)
- 조교용 웹 실습 안내: `website/week{n}_prac.html`

## 기본 구성

별도 요청이 없다면 도전문제 3개와 추가문제 1개로 구성한다. 학습 목표와 진행 순서는 필요한 경우에만 짧게 제시하고, 사용자가 삭제한 도입부는 다시 넣지 않는다. 각 문제는 다음 순서의 셀로 작성한다.

1. 문제 번호와 제목
2. 문제 상황을 보여 주는 그림
3. 문제 상황, 입출력 형식, 조건, 입출력 예시
4. 학생용 스켈레톤 코드
5. 조교용 Solution 코드
6. 테스트 케이스 4개를 담은 Markdown 셀

## 문제 설계 원칙

도전문제는 이론 개념을 단계적으로 적용하도록 구성하되, 단순 문법 확인보다 실제 상황을 해결하는 맥락을 부여한다. 문제 사이에는 난이도와 사고 과정이 자연스럽게 이어지도록 한다. 추가문제는 조교의 별도 설명 없이 풀 수 있어야 하므로 도전문제에서 다루지 않은 자료구조, 알고리즘, 함수 또는 기능을 새로 요구하지 않는다. 이미 배운 요소를 다른 상황에 조합해 연습하도록 만든다.

## 코드 작성 규칙

스켈레톤과 Solution의 전체 구조, 변수명, 입출력 형식은 서로 일치시킨다. 스켈레톤에는 학생이 작성할 핵심 부분만 빈칸이나 안내 주석으로 남기며 정답을 직접 드러내는 힌트는 피한다. Solution은 실행 가능한 완성 코드로 작성하고, 학생이 작성하는 핵심 줄이나 구역에는 `# Sol:` 주석으로 역할을 간략히 설명한다. `None` 처리와 오류 출력은 함수의 반환 규칙과 문제 조건에 실제로 필요할 때만 포함한다.

- 첫 문제처럼 전체 코드 작성이 가능한 문제는 `# To Do`와 힌트 주석만 남긴다. 이후 문제도 새 개념에 집중할 수 있도록 선언부, 입력, 반복문, 부모 클래스 등 필요한 뼈대만 제공한다.
- 힌트는 각 구역에서 구현할 역할을 한 문장으로 적고 작성 공간을 둔다. `pass`를 쓰면 첫 등장 시 용도와 교체 방법을 설명한다.
- `input()`에는 `첫 번째 회원 이름: `처럼 짧은 항목명을 안내 문구로 넣는다.
- 작성 범위나 입력 문구를 바꾸면 문제 안내, Solution 주석, 입출력 예시와 테스트 케이스에도 변경 사항을 반영한다.

## 그림 제작 원칙

각 문제마다 가로형 그림을 하나 제공하고 `images/week{n}/week{n}_chal{k}.png` 또는 `images/week{n}/week{n}_extra{k}.png`처럼 일관되게 저장한다. 새 주차를 제작할 때는 먼저 `images/week{n}/` 폴더를 만든다. 그림은 문제 상황과 입력 대상의 관계를 이해하도록 돕되, 계산식, 정답, 구체적인 풀이 순서를 노출하지 않는다. 노트북은 `practice/`에 있으므로 `<img src="../images/week{n}/week{n}_chal{k}.png" width="600">` 형식으로 삽입한다. 추가문제 그림도 같은 방식으로 `../images/week{n}/`를 참조한다.

## 테스트 케이스

문제마다 정확히 4개를 작성한다. 테스트 케이스 1은 문제에 사용한 예시 입력을 그대로 사용한다. 나머지는 일반 사례, 경계값, 빈 결과 또는 잘못된 입력처럼 서로 다른 동작을 확인하도록 고른다. 모든 출력은 Solution을 직접 실행해 검증한다. 문제 안내의 출력 예시에는 입력 프롬프트가 보일 수 있지만, 테스트 케이스 출력은 채점 기준에 맞춰 프롬프트를 제외할 수 있으며 이 차이를 임의로 통일하지 않는다.

## Markdown과 최종 점검

실습 자료에서는 가운데점 기호를 사용하지 않는다. 입출력 예시와 테스트 케이스의 코드 블록은 언어 이름을 붙이지 않고 세 개의 백틱으로 시작한다. 완성 전에는 다음을 확인한다.

- 노트북 JSON과 모든 셀 ID가 유효하고 중복되지 않는가
- 스켈레톤과 Solution이 같은 요구사항을 구현하는가
- 모든 Solution과 테스트 케이스의 실제 출력이 일치하는가
- 이미지 경로가 유효하며 그림이 정상적으로 열리는가
- 추가문제가 도전문제에서 배운 범위를 벗어나지 않는가
- 사용자 지정 표현과 이미 승인된 수정 사항을 보존했는가
